StrmHub 使用文档

115 网盘直链 · STRM 生成 · TMDB 自动整理入库 · Emby 对接 · 企微/TG 机器人 · 自带观影门户 · 应用内自更新。本页为官方使用 Wiki，随版本更新。

115 网盘STRM 直链播放TMDB 刮削整理洗版策略观影门户企业微信机器人

1简介与功能

StrmHub 把 115 网盘变成你的影视库存储：视频不出网盘，本地只生成体积几乎为零的 .strm 直链文件，Emby/Jellyfin 刮削后即可秒点秒播；配合 TMDB 识别自动重命名、分类入库、洗版与画质补全。

115 网盘→ 转存/离线下载→ 待整理目录→ TMDB 识别·重命名·洗版→ 媒体库（网盘内）→ STRM 落盘→ Emby 刮削播放

核心特性

  • 302 直链代理：STRM 内只存短链，播放时按客户端动态 302 到 115 直链，Emby DirectPlay 不转码
  • 自动整理：TMDB 识别 → 模板重命名（电影/剧集/AV 三套模板）→ 分类入库 → 字幕跟随 → 企微/TG 入库通知（带海报）
  • SHA1 云端去重 + 洗版：直接查网盘目标目录比对，重复不二次入库；按优先级规则自动淘汰旧版本
  • 画质补全：文件名缺分辨率/编码时 ffprobe 探测真实信息后规范命名
  • 增量同步：115 生活事件流驱动，网盘增删改实时映射到本地 STRM
  • 观影门户（6688 端口）：海报墙、分类、搜索、网页播放（直连 → Emby 引擎 → ffmpeg 转封装三级降级）、可选 PIN 码保护
  • 企业微信/TG 机器人：发链接即下载/转存，指令远程整理、同步、查状态
  • 应用内自更新：界面点按钮完成镜像更新，CI 构建完成才提示，失败自动回滚

2部署安装

前置要求

  • 一台能访问 115 与 TMDB 的服务器（国内服务器建议在「系统配置 → 代理」配置代理）
  • 已安装 Docker 与 Docker Compose
  • 115 网盘账号（VIP 更稳）

Docker Compose（推荐）

新建目录 strmhub，保存以下内容为 docker-compose.yml 后执行 docker compose up -d：

services:
  strmhub:
    image: ghcr.io/daisyyijin/strmhub:latest
    container_name: strmhub
    restart: unless-stopped
    stop_grace_period: 20s        # 优雅退出窗口（停 worker、冲刷待发通知）
    ports:
      - "6060:6060"   # 管理后台
      - "6086:6086"   # 302 直链代理 + Emby 反代 + 企微回调
      - "6688:6688"   # 观影门户
    volumes:
      - ./config:/config           # 配置（账号/密钥/设置）
      - ./data:/data               # 数据库
      - ./media:/media             # STRM 本地目录（Emby 读这里）
      - ./logs:/logs               # 日志
      - /var/run/docker.sock:/var/run/docker.sock   # 应用内自更新必需
    environment:
      - TZ=Asia/Shanghai
      # - JWT_SECRET=自定义密钥   # 不设则首次启动自动生成并持久化
💡不挂载 docker.sock 也能正常使用，只是「应用内更新」不可用（只能手动 docker compose pull && up -d）。

3端口与访问

端口服务谁访问
6060管理后台（全部管理界面）你自己（登录保护）

⚠️门户端口必须用 6688：6665–6669 中除 6688 外都在浏览器「不安全端口」黑名单内，会报 ERR_UNSAFE_PORT 打不开。

4首次配置引导

部署后浏览器打开 http://服务器IP:6060，首次访问会要求注册管理员账号（用户名+密码，存在 config/auth.yaml）。登录后仪表盘顶部会出现「配置引导」卡片，按顺序完成：

  1. 绑定 115 账号（账号管理 → 扫码登录，强烈建议同时启用 OpenAPI）
  2. 填写 TMDB API Key（系统配置 → TMDB 配置；themoviedb.org 注册免费获取）
  3. 选择整理目录（自动整理 → 基础配置：待整理 / 已存在 / 冗余 三个目录，点「选择目录」从网盘挑）
  4. 执行首次全量同步（账号同步 → 选择 115 媒体库目录 → 开始全量同步）

四步完成后引导卡自动隐藏。可选进阶：对接 Emby、配置通知、设置门户 PIN。

💡忘记管理员密码？docker exec strmhub ./strmhub --reset-admin 重置账号（其余配置保留）。

5账号管理（115）

两种通道

通道登录方式说明
OpenAPI 推荐AppID + 115 App 扫码授权官方开放平台接口，无 UA 风控、无「服务器开小差」、token 自动续期。在 open.115.com 申请应用拿 AppID
Cookie网页扫码 / 手动粘贴 Cookie兼容性回退通道；设备类型要与 Cookie 来源匹配，否则容易风控

两个通道可以同时配置：OpenAPI 优先，失败自动回退 Cookie。

Cookie 设备

默认「115浏览器_网页端」兼容性最好。如果你粘贴的是 App 端 Cookie，请把设备切成对应的 App 端，UA 不匹配会报「服务器开小差了」。

API 请求间隔

账号页可设 115 API 请求间隔（默认 3 秒）。被风控（报「服务器开小差」）时适当调大；整理/同步变慢属正常。写操作（改名/移动）内部强制 ≥3 秒间隔，读操作更快。

6全量同步

把 115 媒体库完整映射到本地：视频生成 .strm，附属文件（字幕/封面/NFO）实体下载。账号同步页配置：

配置说明
媒体库目录点「选择目录」挑网盘里的库根（如 /影视库），或手填路径自动换算 cid
本地路径STRM 落盘位置，默认 /media（Emby 挂载同目录）
后缀过滤视频/图片/数据文件三组扩展名白名单

STRM 直链设置（系统配置）

配置选项说明
直连域名—302 短链使用的域名/IP（默认取请求 Host，反代后建议显式填写）
直连格式pick_code_name / pick_code前者直链带原文件名（播放器显示友好，推荐）；后者仅文件 ID 最短
保留扩展名开/关STRM 文件名是否带 .mkv 等后缀（Emby 识别格式用，推荐开）
本地已存在时覆盖 / 跳过覆盖=每次全量都重写（改配置后生效，推荐）；跳过=只生成一次
💡全量同步只补不删——网盘删除的清理走「STRM 管理 → 清理孤儿」或增量同步事件。

7增量同步

基于 115 生活事件流：网盘里的上传/删除/移动/改名实时映射到本地 STRM（删旧建新、字幕附属同步处理），无需重复全量。

  • 定时：增量页配置 cron（默认 */10 8-23 * * * 即每天 8–23 点每 10 分钟），下方实时预览未来 5 次运行时间
  • 自动触发：整理完成、转存完成、离线下载完成都会自动补一轮增量
  • 参数继承：目录与后缀过滤沿用全量同步配置，改那里即可
⚠️事件表保留 30 天：停用增量超过 30 天期间的删除会丢失，恢复后跑一次「STRM 管理 → 清理孤儿」对齐。

8STRM 管理

同步台账的可视化管理（侧栏「STRM 管理」）：

  • 列表：搜索路径、「仅看失效」（本地文件已丢失的记录）筛选、有效/失效标记
  • 删除：单条删除会同时清掉本地 strm 文件与台账行
  • 清理孤儿 STRM：扫描本地存在但网盘已删的 .strm——先统计确认再删，只删可再生的 strm（图片/NFO 只统计不动），随时可全量同步重建

9自动整理

把「待整理目录」里的内容识别入库的全自动流水线：

待整理目录→ TMDB 识别→ SHA1 云端去重→ 洗版判定→ 画质补全(可选)→ 模板重命名→ 移入媒体库→ STRM+通知

三个工作区目录（基础配置）

目录用途
待整理新内容的落点：离线下载/转存/手动丢进来都放这，整理从这里取
已存在重复内容（SHA1 相同、或洗版判定新版不优）的去向
冗余无法识别/广告文件/洗版淘汰旧版本的去向
⚠️三个目录不要选在媒体库根或库的上层——系统会熔断增量同步防止误吞事件；选库内子目录或库外目录。

识别规则（识别配置）

  • 替换规则：文件名清洗（如 某站名| 去广告前缀），一行一条正则
  • 最小体积：小于该值的视频直接进冗余（过滤广告/预告片）
  • GPT 辅助（可选）：TMDB 搜不到时用大模型从文件名提取片名/年份再搜，配国内平台（硅基流动等）的 URL/Key 即可

分类策略（YAML）

按 TMDB 属性把影视分到不同子目录（分类名即网盘目录名，支持 / 多级）：

movie:
  电影/动画电影:
    genre_ids: '16'          # TMDB 类型 16=动画
  电影/华语电影:
    original_language: 'zh,cn,bo,za'
  电影/外语电影:              # 兜底（放最后）

tv:
  电视剧/国漫:
    genre_ids: '16'
    original_language: 'zh,cn'
  电视剧/海外剧:

运行方式

  • 整理页手动「开始整理」；定时任务（增量 cron）每轮自动带一次整理
  • 转存/离线下载完成后自动触发整理+增量
  • 整理过程与结果实时输出到日志页；任务进行中全站同步/整理按钮互斥禁用，任务条显示实时进度

10重命名模板

电影/剧集/AV 各有「目录模板 + 文件模板」两套，编辑时下方实时示例预览效果。

默认模板

电影目录：{first_letter}-{title}-{year}-[tmdb={tmdb_id}]
电影文件：{title}.{year}<.{resource_pix}><.{resource_source}><.{resource_type}><.{resource_effect}><.{video_encode}><.{audio_encode}><-{resource_team}>{ext}
剧集目录：{first_letter}-{title}-{year}-[tmdb={tmdb_id}]
剧集文件：{title} - {season_episode}<.{resource_pix}>…（同上）

11洗版策略

同一部影视来了新版本时，按优先级规则决定「新版替换旧版」还是「保留旧版」，旧版自动移入冗余/已存在下的 洗版-旧版本/ 子目录。

电影洗版策略:
  mode: replace        # coexist共存 / skip跳过 / replace替换
  scope: all           # all=全局只留一个最优 / group=按分辨率分组各留一个
  media_type: movie
  old_version_target: redundant   # 旧版去向 redundant / existing
  priority_level:      # 从上到下，首条能分出高下的规则定胜负
  - resource_team: "WiKi"         # 发布组优先
    resource_effect: "!DV.HDR,!DV" # !前缀=排除
  - resource_pix: "2160p"
    resource_type: "BluRay"
  - resource_pix: "1080p"
    resource_type: "BluRay"

剧集洗版策略:          # 剧集按「同一集」比较，新集数直接入库不洗版
  mode: replace
  media_type: tv
  priority_level:
  - resource_pix: "2160p"

可用字段：resource_team（发布组）、resource_pix（分辨率）、resource_type（来源质量）、video_encode / audio_encode（编码）、resource_effect（特效，! 排除）。

12媒体补全

文件名缺分辨率/编码（如 蜘蛛侠.2016.mkv）时，用 ffprobe 探测 115 直链头部（只拉几 MB）拿真实画质，再规范命名。整理时同步探测（探测→改名→入库一步完成），也可发企微指令「补全」扫描全库存量。

决策矩阵（策略可逐项调 rename/keep）

情形默认
名缺画质 + 探测有改名补齐
分辨率相符但缺编码补齐编码
名实冲突（名 1080 探 2160 等）按探测改（跨 2 档视为探测异常保留原名）
命名已完整保留

三种预设模式：保守（尽量不动）、标准（推荐）、激进（完整命名也重排）。

13观影门户（6688）

手机/电脑浏览器直接看片：http://服务器IP:6688

  • 海报墙：最近入库 / 继续观看（进度记忆）/ 分类 / 搜索
  • 播放引擎三级降级：mp4/webm 浏览器直连（零服务器消耗）→ Emby 引擎（秒拖进度、内嵌音轨字幕切换、服务端转码）→ 门户 ffmpeg 转封装（H.265 自动转 H.264）
  • 播放器：0.5–3x 倍速、音轨/字幕菜单（内嵌+外挂）、进度条拖动、iOS 全屏、键盘快捷键（空格播放暂停、←→ 快退快进 10 秒）
  • PIN 保护（系统配置 → 门户访问保护）：设置后打开门户先输 PIN，家人共用一个即可；修改 PIN 所有人需重新验证
⚠️公网部署强烈建议设置 PIN——不设则任何知道地址的人都能浏览并播放你的媒体库。门户播放会占用服务器带宽与 CPU（转码时），并发播放会话有上限保护。

14Emby 对接

服务端配置（系统配置 → EMBY 管理）

  • 服务器地址 + API Key：Emby 后台「设置 → API 密钥」生成；填完点「测试连接」
  • 路径映射：StrmHub 的 /media/xxx 对应 Emby 内的挂载路径（两边挂同一目录则通常不用填）
  • 路径风格：unix / windows（影响通知 Emby 刷新时的路径格式）
  • 入库时刷新：开了才会在 STRM 生成后自动触发 Emby 媒体库刷新

Emby 侧要点

  • Emby 挂载 ./media 目录建库；播放走 302 直链 DirectPlay 不转码
  • 客户端限速/外网播放需要转码时，把 Emby 的串出地址指向 http://服务器IP:6086/emby（6086 是 Emby 反代）
  • 播放通知（开始/结束推送到企微/TG）：Emby 装 Webhooks 插件，URL 填 http://服务器IP:6086/api/emby/webhook?token=界面生成的token

15消息通知与机器人

企业微信

  1. 企业微信后台建自建应用，拿到 企业ID（CorpID）、Secret、AgentID 填入消息配置页
  2. 要双向互动：应用「接收消息」页设 URL 为 http://公网IP:6086/wecom/callback，Token 与 EncodingAESKey 填进消息配置
  3. 保存即自动生成聊天底栏菜单（自动整理 / 增量同步）

  • 任务通知：整理/同步/转存/离线下载完成与失败
  • 播放通知：Emby Webhook 接入后推送播放开始/停止

16离线下载与转存

  • 网页提交：上传下载页粘贴磁力/ed2k/HTTP 链接；115 分享链接在分享同步卡转存（填提取码）
  • 机器人提交：直接发链接（见上一节）
  • 全自动闭环：下载/转存完成 → 守望者检测到目录有内容 → 自动整理 → 增量同步 → 通知你入库结果
  • 离线任务列表实时显示状态；失败任务自动告警

17应用内更新

左下角版本号即更新入口（也可点击版本号手动检查）：

徽章含义
镜像构建中…新代码已推送、CI 还在构建镜像（3~8 分钟），构建完自动变蓝
构建失败CI 构建失败，镜像未发布，去 GitHub Actions 看原因
有新版本镜像就绪，点开看更新内容（提交列表）→「立即更新」

更新流程：拉新镜像 → 创建新容器 → 独立辅助容器完成停旧/启新（主容器不能停自己）。新容器 20 秒内没跑起来不会删除旧容器（保留现场排查），启动失败自动回滚旧容器。前提：compose 挂载了 docker.sock。

18备份与迁移

  • 一键备份：系统配置 →「⬇ 下载备份」得到 zip（全部配置 + 数据库一致性快照）
  • 换机迁移：新机器按第 2 节部署 → 停容器 → 把 zip 内 config/、data/ 解压到对应目录 → 起容器即完整恢复
  • 只搬文件：直接打包宿主机 config/ + data/ 两个目录效果相同

日志在 logs/app.log（10MB 自动轮转保留 3 份），日志页可回看最近 500 行。

19常见问题

播放器/Emby 报「服务器开小差了」？

115 风控。①账号页把 API 间隔调大到 3~5 秒；②确认 Cookie 设备与来源匹配；③建议启用 OpenAPI 通道（无此风控）。

门户 6666 打不开（ERR_UNSAFE_PORT）？

浏览器不安全端口黑名单，门户用 6688。

整理后外挂字幕没挂上？

字幕需与视频同名（语言后缀保留，如 片名.chs.srt）。整理会自动跟随改名；自己放的字幕注意命名。

重新放回同样的文件还是提示「已存在」？

去重按网盘目标目录的 SHA1 比对——你删了库里的文件但目标目录里还有同 SHA1 的其他版本（或移去了已存在目录）。清掉目标目录内同内容即可。

画质补全探测失败？

探测读文件头部，个别封装（moov 在文件尾的 MP4）拿不到信息会保留原名，不影响入库。连续失败多为直链风控，稍后再试或跑「补全」重扫。

更新后要重新登录？

升级到「JWT 密钥随机化」版本时会生成新密钥，旧登录态失效一次，重新登录即可（仅一次）。

机器人没反应？

①回调地址要用 6086 端口且企业微信服务器能访问你的服务器（公网）；②Token/AESKey 与后台一致；③保存配置后菜单自动生成，聊天框没按钮就退出会话重进。

TMDB 识别失败/搜不到？

①检查 API Key；②国内服务器在「系统配置 → 代理」配代理（TMDB 识别走全局代理）；③片名太乱的文件配 GPT 辅助识别；④识别失败的内容留在待整理目录，不会误进冗余（网络瞬断时保护性跳过）。

如何完全重置？

停容器删除 config/ + data/ 后重启 = 全新安装（media/ 里的 strm 也建议清掉重同步）。
